# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

This document records defects identified during the review of the starter implementation of `app/main.py`. The review focuses on input validation, attendance calculations, concurrency, database consistency, pagination, API responses, and query performance.

Each finding describes the affected function or endpoint, the incorrect behavior, how it can be detected, and the corrective action taken in the final implementation.

## Items Reviewed but Not Considered Defects

The following behaviors are intentional and should not be treated as defects when implemented according to the API contract:

1. **Weekend attendance records:** Weekend records can exist and may contribute to late-arrival and overtime metrics. Weekends are excluded from working-day attendance counts.
2. **Attendance status handling:** `PRESENT`, `WFH`, and `ON_DUTY` count as present. `ABSENT` and `LEAVE` do not count as present.
3. **Late-arrival grace period:** An arrival exactly 10 minutes after shift start is not late under the strict greater-than-10-minute rule.
4. **Overtime threshold:** Overtime below 30 minutes is not recorded as qualifying overtime.
5. **Half-day threshold:** Rounded work hours of exactly 4.50 do not qualify as a half-day.
6. **Employees without attendance logs:** Employees who joined by the reporting period's end should still be included in eligible department headcount.
7. **Regularization audit history:** Punch-in and punch-out operations do not create regularization-history entries. History is intended for manual corrections.
8. **Internal MongoDB identifiers:** The database may use `_id` internally, but it should not be exposed in API response documents when the contract excludes it.

## Validation

The final implementation was tested using pytest. The recorded test run completed with 12 passing tests and two deprecation warnings.

The tests cover attendance calculations, rounding boundaries, overnight shift handling, status validation, selected aggregation expressions, and duplicate punch-operation behavior.

Additional integration testing should verify true concurrent requests against MongoDB, index usage with a large dataset, and whether each explain operation reflects the complete query used by its corresponding endpoint.
